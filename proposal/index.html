MARCmin · Research proposal · Draft, November 2026

Catalog-Guided Reading Agents

Smaller models that read can beat bigger models that memorize. This project tests that claim by giving a small model the map libraries already built, and measuring how small it can be.

By Chris Markman

01

Scale is the expensive path

Frontier models try to hold what they know in their weights. That takes data centers to train and run, and the knowledge freezes on the day training ends.[1]

02

Libraries already built the map

Catalog records, subject headings and classification organize recorded knowledge into a structure a machine can navigate. Most AI search ignores it.

03

Reading beats remembering

A model that finds the right book and reads the right passage answers from sources it can cite. Its knowledge grows as the collection grows, without retraining.[2, 3]

04

So search for the minimum

The question is not how big a model you can afford. It is how small a model can be and still read well enough to learn.

Summary

This project builds a question-answering system that knows the map of recorded knowledge rather than all of its contents. It embeds the Library of Congress catalog and uses the library's own subject structure to choose books. It reads the relevant passages before answering, and keeps cited notes so its answers improve over time.

The first study is small and testable on its own, and it has a public benchmark: the Library of Congress's own embedded catalog.[4] Does turning MARC21 records into readable text (a pre-encoder) improve catalog search? Does the gain grow as models get smaller? Its test set and results become the foundation for the larger agent.

Libraries have spent a century organizing knowledge with subject headings and classification. The "collections as data" movement already asks libraries to make collections ready for computation.[5] This project applies the idea to the catalog's own structure. An agent that browses it like a reference librarian should find better sources, at lower cost, with reasoning a person can check.

Research questions

Each question can be answered with an experiment. Each has a result worth publishing whichever way it comes out.

Q1 · Phase 1

Readable map

Does serializing MARC records into labeled text improve retrieval over raw records?

HypothesisIt does for every embedding model tested, with a larger gain for small models. A few rules (code expansion, subject strings, field order) account for most of it.[6, 7]

Q2 · Phase 2

Navigation

Does an agent that navigates subject headings and classification find better sources than similarity search alone?

HypothesisCombining hierarchy browsing with vector search beats either alone on topical questions. Its search path is also easier for people to verify.[8, 9]

Q3 · Phase 3

Cumulative notes

Can cited notes from past reading improve later answers without compounding errors?

HypothesisA note library with source links and a verification step raises answer quality over time. Without verification, quality drifts.[10]

Q4 · Phases 1 to 3

Minimum viable model

How small can a model be and still match a large model answering from memory, or the Library of Congress's large-model embeddings?

HypothesisMuch smaller than expected, as long as it stays above a comprehension floor.[3, 11] Below that floor, no catalog map helps. Navigation is where the floor is likely highest.[12]

What would prove it wrong

Small models can't read reliably at any size cheap enough to matter. Navigation adds cost without finding better sources. Notes drift even with checking. Any of these is a useful finding.

The benchmark: the Library of Congress embedded catalog

In October 2026 the Library of Congress turned its catalog into embeddings with a large cloud model and published the files.[4] It used descriptive fields only, and it has not reported how well the result finds things. That makes it the natural benchmark for this project.

20.3 millioncatalog records embedded
1,024dimensions per record, from a large hosted model
Nonesearch-quality scores in the announcement

The test: on the same records and the same judged questions, can a small model on one local machine, reading pre-encoded records, match or beat the national library's large-model embeddings?

If it can, the thesis holds at national scale. If it can't, the gap shows how large the minimum model must be.

Approach

Each phase produces a publishable result on its own, so the project has value even if later phases stall. Pick a phase to see its plan.

Month 1Month 5Month 14

Bar lengths follow the estimates. The striped end of Phase 2 is its uncertain extra three months.

Phase 1: the pre-encoder study

Build a test set of 5,000 to 10,000 real MARC records and 100 to 200 real questions judged by catalogers. Compare raw MARC, the full serializer, the serializer with each rule removed, a compact template and field-aware encoding. Add two baselines: the Library of Congress's descriptive-fields approach, and a serializer with its fields in random order.[4, 7]

Run 3 or 4 embedding models of different sizes plus a keyword baseline. Score the Library of Congress embeddings on the same questions as the benchmark. Report on LCSHBench too, an existing subject-heading test set.[13] Measure speed and power on low-power hardware. The MARCmin site becomes the companion demo, rerun on real data.

Answers Q1 and starts Q4.

Phase 2: the catalog-guided agent

Start from the Library of Congress embeddings instead of re-embedding 20 million records.[4] Give an agent tools to search by similarity, browse Library of Congress Subject Headings (broader, narrower and related terms) and browse classification ranges.

Test navigation at several model sizes from the start. An earlier tree-navigating reader needed models over 70B parameters.[12] If small models fail out of the box, train a small navigator, and filter each step with embeddings as eBay does with its category tree.[9]

The agent retrieves passages from available full text and answers with citations to specific books and pages.

Answers Q2. See recorded runs on the real catalog in Chapter 3.

Phase 3: cumulative notes and the minimum model

The agent writes short notes from what it reads, each linked to its source passage. A verification step checks each note against its source before it is reused.

Answer quality is measured over time with and without the notes, and with and without verification. The same runs repeat across model sizes and hardware to find the smallest model that holds up.

Answers Q3 and Q4. See the example note in Chapter 4.

Evaluation

Every phase reports quality and cost side by side. The thesis is about doing more with less, so cost is a result, not a footnote.

Retrieval

Recall@10, nDCG@10 and MRR on the judged test set, with significance tests. Every result is reported next to the Library of Congress benchmark.

Answers

Expert review for correctness, how many claims are cited and whether the citations are accurate. For Phase 3, the same question set is scored repeatedly over time.

Efficiency

Answer quality per watt, per dollar and per second, across model sizes and hardware tiers. This is the direct test of Q4. Smaller vectors cost little quality: binary vectors keep about 96% of retrieval quality at 1/32 the size.[15]

Expected contributions

  • An open test set for catalog search: MARC records, real questions and expert judgments.
  • A measured, open-source MARC pre-encoder.
  • An agent design that uses library knowledge organization as a navigation tool.
  • Evidence on whether self-written notes help or hurt over time.
  • A measured answer to how small a reading model can be.

Related work

From a first-pass review in November 2026. No published study yet compares raw and serialized MARC for retrieval across model sizes.

  • Retrieval instead of scale. Retrieval lets far smaller models match larger ones, especially on less popular facts.[1, 2, 3]
  • Structured data as text. Serialization format and field order change results.[6, 7]
  • AI over library catalogs. The Library of Congress embedded catalog, a subject-heading benchmark, a synthetic bibliographic benchmark and an agentic indexing pipeline.[4, 13, 16, 17] All appeared in 2026, and none measures patron search on MARC.
  • Navigating hierarchies. Navigation beats flat retrieval on well-organized corpora, but early tree readers needed large models.[8, 9, 12]
  • Memory in agents. Self-written notes help, but unverified notes compound errors.[18, 19, 10]
  • Small models and small vectors. Small models need search to supply facts; embeddings can be shortened or quantized.[11, 20, 15]
  • Collections as data. The library movement this work extends.[5]

Risks and fallbacks

Full-text access is narrower than hoped

Fall back to public-domain text plus summaries and tables of contents, and report the coverage bias.

Phase 1 shows little gain for large models

That is still a publishable result. Shift the emphasis to small models and cost.

Notes compound errors

Phase 3 is designed to measure exactly that. A negative result is useful.

Small models can't navigate

Earlier tree-navigating readers failed below 70B parameters.[12] Fall back to embedding-filtered steps or a fine-tuned small navigator, and report the size where navigation starts to work.

Others publish similar work first

Now watched, not unknown: three related projects appeared in 2026.[4, 13, 16] None measures patron search on MARC. The test set and the small-model angle remain distinct.

Next steps

The immediate goal is Phase 1 results and a short paper within about four months. Those results are the evidence for everything after.
